_______:  systemctl ...
	- I disabled the services , to start them manualy! had to start docker (?: kubelet req? ist still disabled/not-running! and nodes are running ok ...!)
	systemctl disable --now  containerd.service  crio.service  docker.service  docker.socket  firewalld.service  kubelet.service
	systemctl restart docker.service  docker.socket  ###---> triggers also containerd.service as its container-runtime! (CRI-O is uninstalled! but could also work!?)
	systemctl list-unit-files  -t service  | grepi -E 'container|crio|docker|firewall|kube|runc'  |sort  | sed 's@                 *@                @'  ##--shows if installed and enabaled/disabled ! omit -t xxx to see all: also devices/mounts/...
	systemctl list-units -q --type=service | grepi -E 'container|crio|docker|firewall|kube|runc'  |sort  | sed 's@                 *@                @'   ##--shows if running now!

_______:  cluster create/mgm/delete/...:
	- pre-create:  mvde .kube/config   ##--move/remove old/prev kubeconfigs; a new one will be created by "create cluster" /OR specify alternative config with  --kubeconfig xxx
	- ! kind create cluster --help
	- kind create cluster ----config <cluster1.yml>   --name <your-cluster-name instead kind-kind>  --kubeconfig <create config.yml ...

	--- default-/std-create-cluster:
	kind create cluster --help
	default-cluster-name  ==  kind-kind   ,  default-create-kubeconfig-file  ==  ~/.kube/config
	kind create cluster  --name <your-cluster-name instead kind-kind>  --kubeconfig <create config.yml there instead in ~/.kube/...>
	- ! cluster access configuration is stored in ${HOME}/.kube/config if $KUBECONFIG environment variable is not set.
	- ! default cluster-name for "create cluster ..." is "kind" and all its cluster names are prefixed with "kind-"!
		so your clusrter name is kind-kind (if you did not specify own name with: kind create cluster --name mycluster1):
		kubectl :  to specify the cluster name to interact/query with kubectl (if you have multiple entries in your kubeconfig file), do:  kubectl cluster-info --context <cluster-name>

	- kind itself is a docker/container and using Docker container “nodes”. So basically you can use all docker-cli-cmds to it ...
	docker exec -it kind-control-plane  crictl images   ##-bzw. set kind-control-plane to your cu-kind-node-name ! kind-control-plane is default-name only but can be adapted during cluster create --name ...
